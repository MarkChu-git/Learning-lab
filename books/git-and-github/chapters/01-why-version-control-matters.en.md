## What this chapter is about

This opening chapter is designed to fix the most common beginner mistake:

> learning a few Git commands without first understanding why version control exists at all.

The chapter therefore starts before commands, before GitHub pages, and before branching details. Its goal is to establish the right mental model.

## Core themes in the Chinese chapter

1. **Most people do not fail because they never saw commands**
   - They fail because they never built a clear model of what Git is managing.

2. **Ordinary file management breaks down quickly**
   - overwriting old files,
   - duplicating files with names like “final-v2-final-really-final”,
   - sending files around in chat or cloud folders,
   - and relying on memory are all weak substitutes for version history.

3. **Version control is really about managing change**
   - what changed,
   - when it changed,
   - who changed it,
   - why it changed,
   - and whether it can be compared or rolled back.

4. **Git is not the same thing as cloud sync**
   - synchronization matters,
   - but Git’s real core is local history management.

5. **Git is not the same thing as GitHub**
   - Git is the version control system.
   - GitHub is a collaboration and publishing platform built around Git repositories.

6. **The mental shift is the real difficulty**
   - Git asks users to move from “editing files directly” to “managing tracked change explicitly.”

7. **Git is useful beyond programming**
   - textbook writing,
   - documentation,
   - knowledge-base maintenance,
   - reports,
   - collaborative projects,
   - configuration and automation.
