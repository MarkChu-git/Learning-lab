# 《Git 与 GitHub》

> 语言 / Language：**中文** | [English](README.en.md)

很多人第一次接触 Git 时，都会觉得它"很重要但很难学"。他们背下了几条命令，却在遇到分支、冲突、回滚时手足无措；他们知道 GitHub 很流行，却分不清它和 Git 到底是什么关系。

这种困境的根源，往往不是 Git 本身太难，而是学习路径出了问题——大多数人一开始学的不是"版本控制在解决什么问题"，而只是"几条命令怎么敲"。

这一册教材的目标，不是把 Git 写成一份命令速查表，也不是把 GitHub 写成一个"点哪里、按哪里"的网站操作说明，而是把下面这些问题系统讲清楚：

- 版本控制到底在解决什么问题
- 为什么很多人会背命令，却依然把 Git 用得很痛苦
- Git 和 GitHub 分别负责什么，不应该混成什么
- 个人写作、代码协作、发布流程、分支管理、回滚与审阅，为什么都绕不开这一套体系

因此，这一册会同时讲清三条线：

- **概念线**：版本控制、提交、分支、远程仓库、协作关系
- **操作线**：初始化、提交、查看历史、分支、合并、同步、回滚
- **工作流线**：个人使用、双机同步、团队协作、发布与审阅

## 适合谁读

这册教材主要面向以下几类读者：

**第一类：完全新手**  
从来没有真正学过 Git，只知道它"很重要"，但始终不敢上手。你可能听说过 `git commit`、`git push`，但不知道它们到底在做什么，也不知道从哪里开始学起。

**第二类：会用但不懂**  
已经会 `clone`、`add`、`commit`、`push`，日常工作勉强能应付，但一遇到分支、冲突、回滚、rebase 就开始慌。你能照着教程敲命令，但心里其实没底，不知道这些命令背后到底发生了什么。

**第三类：用过但混乱**  
已经在用 GitHub，但仍然分不清本地仓库、远程仓库、分支、PR、fork、sync 各自处在什么位置。你可能在网站上点过很多按钮，但总觉得这些操作之间缺少一条清晰的逻辑线。

**第四类：想用得更好**  
想把 Git / GitHub 用到长期写作、知识库维护、教材迭代和项目协作中，但不确定应该建立什么样的工作流。你知道 Git 很强大，但不知道如何把它的能力真正用到自己的工作中。

## 写作范围

本册将逐步覆盖以下内容：

1. 版本控制的基本思想，以及 Git 和传统"文件备份"思路的差异。
2. Git 的核心对象与工作区模型：工作区、暂存区、提交历史。
3. 初始化仓库、提交、查看历史、比较差异、撤销与回滚。
4. 分支、合并、rebase、冲突及其背后的逻辑。
5. 远程仓库、`fetch`、`pull`、`push` 与同步关系。
6. GitHub 中的仓库、README、Issues、Pull Requests、Fork、Actions 等平台协作概念。
7. 从个人工作流走向团队协作与发布流程的实践方法。

## 学习这一册的建议

如果你是第一次系统学习 Git，建议按照以下方式阅读：

**第一步：建立心智模型**  
先读第一章，理解版本控制到底在解决什么问题。不要急着敲命令，先把"为什么需要 Git"这个问题想清楚。

**第二步：理解核心概念**  
在开始学命令之前，先理解工作区、暂存区、提交历史、分支、远程仓库这些核心概念。它们不是孤立的，而是一个完整的体系。

**第三步：动手实践**  
等概念清楚了，再开始动手。这时你会发现，命令不再是需要死记硬背的咒语，而是自然而然的操作。

**第四步：建立工作流**  
最后，把学到的知识应用到实际工作中。无论是个人写作、知识管理，还是团队协作，都可以找到适合自己的 Git 工作流。

记住：学 Git 的关键不是背命令，而是理解它的工作模型。只要模型清楚了，命令自然就顺了。
