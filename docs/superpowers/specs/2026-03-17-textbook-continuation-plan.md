这是一个双语（中英文）教材合集项目，目标是把不同主题写成真正可读、可学、可复习的长期教材。

**当前状态**：

- **Git 与 GitHub 分册**：已完成第0-2章（快学版 + 2个正式章节）

### 1.2 核心目标

本次编写计划的核心目标：
1. **并行推进**两个分册，保持同步进展
2. **面向0基础初学者**，用通俗易懂的语言讲解
3. **实战案例驱动**，每个知识点都配完整的实战场景
4. **中英文同步**，信息量完全一致

#### 第3章：回看与回退——如何查看历史、比较差异并安全撤销

**字数**：8,000-10,000字（中文版）
**深度**：进阶级
**核心目标**：让0基础读者理解 Git 的"时间旅行"能力

**内容大纲**：
1. 为什么需要回看历史（800字）
   - 实战场景：代码突然出问题，需要找到是哪次提交引入的
   - 版本控制的核心价值：可追溯性

2. 查看提交历史的多种方式（2500字）
   - `git log` 基础用法与常用选项
   - `git log --oneline --graph --all`：可视化分支历史
   - `git log -p`：查看每次提交的具体改动
   - `git log --grep`、`git log --author`：搜索特定提交
   - `git show`：查看单个提交的详细信息
   - 实战案例：找到引入 bug 的提交

3. 比较差异的完整模型（2000字）
   - 工作区 vs 暂存区：`git diff`
   - 暂存区 vs 最新提交：`git diff --staged`
   - 任意两个提交之间：`git diff commit1 commit2`
   - 查看特定文件的差异
   - 实战案例：确认即将提交的内容是否正确

4. 撤销操作的三种武器（3000字）
   - `git restore`：撤销工作区或暂存区的修改
   - `git reset`：移动 HEAD 和分支指针
     - `--soft`：只移动 HEAD
     - `--mixed`（默认）：移动 HEAD 并重置暂存区
     - `--hard`：移动 HEAD、重置暂存区和工作区
   - `git revert`：创建新提交来撤销旧提交
   - 三者的本质区别与使用场景（用通俗语言解释）

5. 实战场景演练（1500字）
   - 场景1：刚修改了文件，还没 add，想撤销
   - 场景2：已经 add 了，但还没 commit，想撤销
   - 场景3：已经 commit 了，但还没 push，想撤销
   - 场景4：已经 push 了，需要撤销（只能用 revert）
   - 场景5：找回"丢失"的提交（reflog）

6. 安全撤销的原则（800字）
   - 什么时候可以用 reset --hard
   - 为什么 push 后不应该用 reset
   - 如何避免数据丢失

### 3.1 面向0基础的核心原则

**目标读者**：完全没有 Git 或 Markdown 经验的初学者

**语言风格**：
1. **避免术语堆砌**
   - ❌ "使用 HEAD 指针进行 detached HEAD 状态的导航"
   - ✅ "HEAD 是 Git 用来标记'你现在在哪里'的指针，有时候它会进入一种特殊状态..."

2. **多用类比和比喻**
   - Git 的三层模型 → 草稿本、待发布区、已发布档案
   - 分支 → 平行宇宙
   - 远程仓库 → 云端备份
   - Pull Request → 请求合并代码

3. **从"为什么"开始**
   - 每个概念都先讲"为什么需要"
   - 再讲"是什么"
   - 最后讲"怎么用"

4. **循序渐进**
   - 一次只引入一个新概念
   - 新概念建立在已学概念之上
   - 避免前置知识跳跃

**段落结构**：
- 每段不超过200字
- 复杂概念分多段讲解
- 使用小标题分割内容
- 重要内容用引用块或加粗突出

### 3.2 章节结构模板

### 3.3 代码示例规范

nothing to commit, working tree clean

### 3.4 实战案例规范

5. **可能遇到的问题**
